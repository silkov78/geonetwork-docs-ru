# Версионирование

Каталог метаданных Национального геопортала имеет встроенный механизм для отслеживания истории изменения записей метаданных - система версионирования. Данный механизм позволяет администраторам и редакторам групп просматривать историю правок записей, сравнивать их различные версии между собой и, при необходимости, восстанавливать предыдущие состояния метаданных.

Эта функция может быть критически важна для обеспечения качества данных, аудита действий пользователей и восстановления информации в случае ошибочного редактирования записей.

## Активация системы версионирования

По умолчанию система версионирования может быть отключена в отдельных субпорталах. Для её активации администратор субпортала должен выполнить следующие действия:

1. Выбрать в выпадающем меню `Администрирование` пункт `Настройки`.

2. Откроется раздел **Системные настройки**, в котором нужно перейти в раздел `Метаданные`. В этом разделе нужно найти группу `История`, в котором будет вкладка `Версионирование`.

3. Во вкладке **Версионирование** активируйте опцию `Включить версионирование` и сохраните выбранную настройку.

## Создание версии записи

Новая версия (ревизия) записи создается автоматически каждый раз, когда пользователь сохраняет изменения в редакторе метаданных. В данном случае будет реализован следующий сценарий:

1. Пользователь (имеющий права на создание и редактирование записей в субпортале) открывает запись метаданных в режиме редактирования.

2. В записи вносятся требуемые изменения.

3. Пользователь нажимает кнопку `Сохранить`, система предложит ввести комментарий к изменению. Данное действие необязательно, но рекомендуется к выполнению, так как повышает прослеживаемость изменений и облегчает совместную работу разных специалистов над записью. Комментарий рекомендуется составлять по возможности кратко, описывая только суть внесенных правок, например, "Обновление контактных данных" или "Исправление опечаток в аннотациях".

Каждое сохранение увеличивает порядковый номер ревизии записи и сохраняет снимок XML-файла метаданных в истории изменений.

## Просмотр истории изменений записи

1. Следует открыть запись метаданных в режиме просмотра или редактирования.

2. В меню действий с записью будет доступна кнопка `История`:

3. По нажатию на кнопку **История** откроется таблица, содержащая следующую информацию:

* Номер версии (ревизии) записи.

* Дата и время изменения.

* Имя пользователя, создавшего ревизию.

* Статус записи ("Изменено", "Создано").

* Комментарий к ревизии (если он был создан).

## Сравнение версий записей

Механизм версионирования Каталога метаданных позволяет визуально сравнить две версии записи, чтобы иметь наглядное представление о степени изменения записи.

1. Открыв [историю изменений записи](#просмотр-истории-изменений-записи), пользователь может выбрать две версии, которые он хочет сравнить между собой:

2. Теперь пользователю будет доступна кнопка `Сравнить`:

3. Система отобразит обе версии в окне рядом друг с другом и предоставит отчёт о различиях версий:

- Зеленым цветом (знаком "+") будут выделены добавленные элементы или строки.

- Красным цветом (знако "-") будут выделены удалённые элементв.

- Измененные значения будут показаны в контексте **Было** -> **Стало**.

## Восстановление предыдущей версии

Если в запись были внесены изменения по ошибке или есть необходимость вернуться к предыдущей ревизии записи, то пользователь имеет возможность "откатить" версию к любому предыдущему состоянию.

1. Открыв [историю изменений записи](#просмотр-истории-изменений-записи), пользователю нужно найти ту версию записи, к содержанию которой он хочет вернуть текущее содержание записи.

2. Выбрав нужную версию, пользователь должен найти напротив неё кнопку `Восстановить` и нажать на неё.

3. Пользователь подтверждает действие, нажав кнопку `Сохранить`:

!!! warning "Предупреждение"

    Восстановление предыдущей версии записи создаёт *новую* её версию, со своим порядковым номером. Эта *новая* версия по сути будет являться точной копией выбранной предыдущей версии записи. Таким образом, история промежуточных изменений не будет удалена, что позволит, при необходимости, отменить даже сам процесс восстановления к какой-либо версии в истории изменений записи.

## Удаление записи и история

В настройках версионирования администратор субпортала должен установить политику действий при удалении записей с активированной функцией версионирования, так как в зависимости от этого, история версий может либо **архивироваться** при удалении записи, либо **удаляться** окончательно вместе с ней.

Если в субпортале настроена система **Корзины**, то удалённая запись будет помечена как удалённая, но её история изменений будет храниться в базе данных до момента окончательной очистки корзины администратором субпортала.
