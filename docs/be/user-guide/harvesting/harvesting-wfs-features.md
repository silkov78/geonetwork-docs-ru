# Збор метаданых з WFS-сервера {#getfeature_harvester}

Метаданыя могуць прысутнічаць у табліцах рэляцыйных баз даных, якія часта выкарыстоўваюцца многімі арганізацыямі.
Выкарыстанне пратакола WFS паверх рэляцыйнай базы даных дазволіць здабываць метаданыя з дапамогай стандартных механізмаў запыту.
Гэты тып збору даных дазваляе карыстальніку задаць запыт GetFeature, атрымаць інфармацыю з WFS-аб'ектаў і занесці ёй у шаблон для стварэння запісаў метаданых.

## Даданне WFS-зборшчыка

WFS рэалізуе аперацыю запыту GetFeature, якая вяртае даныя ў выглядзе аб'ектаў (звычайна радкоў з табліц у рэляцыйнай базе даных).
GeoNetwork, дзейнічаючы ў якасці кліента, можа прачытаць адказ GetFeature і прымяніць XLST-пераўтварэнне для стварэння фрагментаў метаданых,
якія можна звязаць або скапіяваць у прадстаўлены карыстальнікам шаблон для стварэння запісаў метаданых.

Даступныя наступныя опцыі:

- **Ідэнтыфікацыя** - параметры сабраных даных у каталогу GeoNetwork.
    - *Імя* - Гэта кароткае апісанне аддаленага сайта. Яно будзе паказана на галоўнай старонцы збору ў якасці імя для гэтага асобніка CSW-харвестара.
    - *Выбар лагатыпа* - Лагатып будзе выкарыстоўвацца пры адлюстраванні сабраных запісаў метаданых у выніках пошуку.
    - *Група* - Група, у якой размесцяцца метаданыя, якія збіраюцца.
    - *Карыстальнік* - Карыстальнік, які будзе ўладальнікам сабраных метаданых.
- **Расклад** - Параметры раскладу, паводле якіх зборшчык будзе збіраць метаданыя.
    - *Частата* - Частата (перыядычнасць) запуску збору метаданых харвестарам.
    - *Толькі адзін запуск* - Зборшчык будзе запушчаны толькі адзін раз, калі абраны пункт.
- **Наладзіць падключэнне** - параметры падключэння да CSW-сервера.
    - *URL сэрвісу* - URL CSW з параметрамі GetCapabilities або без іх. Напрыклад, <http://geonetwork-site.com/srv/eng/csw?service=CSW&request=GetCabilities&version=2.0.2>.
    - *Аддаленая аўтэнтыфікацыя* - Уліковыя даныя для базавай HTTP-аўтэнтыфікацыі на серверы CSW (Лагін і Пароль).
    - *Запыт WFS GetFeature* - Запыт OGC WFS GetFeature, які выкарыстоўваецца для здабывання функцый з WFS.

- **Апрацоўка адказу wfsfeatures**
    - *Праверка запісаў перад імпартам* - Праверка запісаў перад імпартам.
    - *Мова*
    - *Стандарт метаданых*
    - *Захаваць вялікі адказ на дыск* - Усталяваны сцяжок азначае, што адказ WFS GetFeature будзе вялікім (напрыклад, больш за 10 МБ). Калі гэты сцяжок усталяваны, адказ GetFeature будзе захаваны на дыску ў часовым файле. Затым кожны аб'ект будзе выняты з часовага файла і выкарыстаны для стварэння фрагментаў і запісаў метаданых. Калі сцяжок не ўсталяваны, адказ будзе захоўвацца ў аператыўнай памяці.
    - *Табліца стыляў для стварэння фрагментаў* - табліца стыляў, якая прадастаўляецца карыстальнікам, якая пераўтворыць адказ GetFeature у дакумент фрагментаў метаданых (фармат гэтага дакумента гл. ніжэй). Табліцы стыляў існуюць у каталогу WFSToFragments, які знаходзіцца ў каталогу пераўтварэння абранай выходнай схемы. напрыклад. для схемы iso19139 гэта каталог GEONETWORK_DATA_DIR/config/schema_plugins/iso19139/convert/WFSToFragments.
    - *Пошук дублікатаў рэсурсаў па ідэнтыфікатары рэсурсу* - Параўнанне выканана па элеменце 'gmd:identificationInfo/*/gmd:citation/gmd:CI_Citation/gmd:identifier/*/gmd:code/gco:CharacterString'. Яно прыдатна толькі да запісаў па ISO19139 або профілях ISO.
    - *Катэгорыя выходных запісаў метаданых*
    - *Стварыць падшаблоны* - Стварыць падшаблоны для кожнага аб'екта WFS.
    - *Выберыце шаблон для аб'яднання з фрагментамі*
- **Даступнасць для сабраных запісаў** - Прызначэнне прывілеяў пэўным групам па сабраных метаданых.
    - *Калі запіс існуе* - Прымяняецца толькі пры абнаўленні, і калі пры канфлікце UUID прадпісана зададзена перапісваць запісы. Калі ўключана, прывілеі не выдаляюцца пры абнаўленні.

## Падрабязней пра пераўтварэнне адказу GetFeature ў фрагменты метаданых

Унутры каранёвага элемента <record> можа быць ад нуля да мноства элементаў <record>.
Пры генерацыі метаданых кожны элемент record прывядзе да стварэння аднаго дакумента метаданых.
У адваротным выпадку элемент <record> выкарыстоўваецца толькі для групоўкі фрагментаў метаданых (напрыклад, фрагментаў, згенераваных для набору даных або аб'екта).

Унутры элемента <record> можа быць ад нуля да мноства элементаў <fragment> і ад нуля да мноства элементаў <replacementGroup>.
Элемент <replacementGroup> сам можа ўтрымліваць ад нуля да мноства элементаў <fragment>.
Парадак размяшчэння элементаў <fragment> і <replacementGroup> унутры элемента <record> ці <replacementGroup> не важны.

Элементы <fragment> ўтрымліваюць асобныя xml-фрагменты. Змесцівам <fragment> можа быць любы xml-элемент з падтрымоўванай схемы GeoNetwork пры ўмове,
што элемент павінен утрымліваць дастатковую колькасць адпаведных метаданых, якія дазваляюць ідэнтыфікаваць мэтавую схему (г.зн. адрозніваць прасторы імёнаў).

Элементы <replacementGroup> маюць значэнне толькі пры генерацыі метаданых.
Яны выкарыстоўваюцца для групоўкі фрагментаў для ўстаўкі або стварэння спасылак у копіі шаблона метаданых, які выкарыстоўваецца для генерацыі метаданых.
Калі элемент <replacementGroup> не ўтрымлівае элементаў <fragment>, элемент, на які спасылаецца копія шаблона, будзе выдалены.
У адваротным выпадку ён будзе заменены змесцівам фрагмента.

Дапушчальныя атрыбуты гэтых элементаў і іх функцыя заключаюцца ў наступным:


| Элемент            | Атрыбут | Апісанне                                                                                                                          |
|--------------------|---------|-----------------------------------------------------------------------------------------------------------------------------------|
| <record>           | Uuid    | Uuid згенераванага запісу метаданых (неабавязкова - у адваротным выпадку ён будзе прызначаны зборшчыкам)                          |
| <fragment>         | Id      | Ідэнтыфікатар элемента ў шаблоне метаданых для замены/спасылкі на яго. Ігнаруецца, калі фрагмент знаходзіцца ў групе замены.      |
|                    | Uuid    | Uuid, які будзе выкарыстоўвацца для згенераванага падшаблона (выкарыстоўваецца для спасылкі на гэты падшаблон з метаданых).       |
|                    | Title   | Загаловак фрагмента - выкарыстоўваецца ў якасці загалоўка xlink.                                                                  |
| <replacementGroup> | Id      | Ідэнтыфікатар элемента ў шаблоне метаданых, які неабходна выдаліць, замяніць або звязаць са змешчанымі ў ім фрагментамі.          |

Ніжэй прадстаўлены 2 прыклады, як збіраць метаданыя з функцый камбайна OGC WFS, выкарыстоўваючы табліцы стыляў і шаблоны, якія пастаўляюцца з GeoNetwork.


## Прыклад збору даных пра межы падключанага геасервера (МАШЫННЫ ПЕРАКЛАД)

У гэтым прыкладзе мяркуецца, што геасервер, які пастаўляецца з GeoNetwork, быў падключаны.
Канчатковым вынікам гэтага прыкладу будзе 251 запіс метаданых ISO19139, якія ўтрымліваюць спасылкі на 1506 фрагментаў (па 6 на запіс),
створаных з адказу GetFeature для шэйп-файла boundaries у асобніку GeoServer, які пастаўляецца з GeoNetwork. Створаныя запісы ўтрымліваюць метаданыя пра краіны свету.

Трэба зрабіць наступныя крокі:

- У `Адміністраванне`->`Налады`->`XLink метаданых` уключыце распазнавальнік XLink і *Захавайце* канфігурацыю ў базе даных.

- Дадайце зборшчык *OGC WFS GetFeature* у меню `Адміністраванне`->`Збор даных`.

- Прысвойце яму *Імя* (напрыклад, gboundaries) і ўвядзіце URL-адрас службы wfs з падключанага геасервера (напрыклад, <http://localhost:8080/geoserver/wfs>) у полі *URL-адрас службы*.

- Далей будзе выкарыстаны просты запыт GetFeature, каб выбраць усе краіны з шэйп-файла boundaries, размешчанага за WFS.
  XML для такога запыту (які павінен быць уведзены ў тэкставую вобласць *GetFeature Query*), з'яўляецца:

    ``` xml
    <wfs:GetFeature service="WFS" version="1.1.0"
        xmlns:wfs="http://www.opengis.net/wfs">

      <wfs:Query typeName="gboundaries"/>

    </wfs:GetFeature>
    ```

- Выберыце схему *iso19139*, паколькі ў гэтай схеме ёсць прыклады табліц стыляў і шаблонаў, якія патрэбныя для гэтага прыкладу. Звярніце ўвагу, што пасля выбару гэтага параметру становяцца бачныя наступныя параметры, і мы зробім наступныя дзеянні:

    - Выберыце прыкладаемую табліцу стыляў "geoserver_boundary_fragments", каб выняць фрагменты з адказу GetFeature ў расчыняючымся спісе "Табліца стыляў", які будзе выкарыстоўвацца для стварэння фрагментаў. Гэтую табліцу стыляў можна знайсці ў "GEONETWORK_DATA_DIR/config/schema_plugins/iso19139/convert/WFSToFragments`.
    - Выберыце прыкладаемы шаблон "Geoserver WFS Fragments Country Boundaries Test Template" з расчыняючагася спісу *, які будзе выкарыстоўвацца для стварэння метаданых з выкарыстаннем фрагментаў*. Гэты шаблон можна знайсці ў раздзеле "GEONETWORK_DATA_DIR/config/schema_plugins/iso19139/templates/geoserver_fragment_tester.xml`.

- Выберыце катэгорыю для запісаў, створаных harvester, усталюйце сцяжок "Толькі для аднаго запуску", дадайце некаторыя прывілеі (прасцей за ўсё прадаставіць усім карыстальнікам правы на прагляд). На гэтым этапе ваша форма заяўкі на ўдзел у harvester павінна выглядаць так, як паказана на наступным скрыншоце.

- *Захавайце* форму заяўкі на ўдзел у харвестэры.

- Вярніцеся ў меню "Аперацыі з харвестарам", дзе зможаце "Актываваць" харвестар, а затым "Запусціць" яго.

На старонцы вынікаў паказана, што з адказу WFS GetFeature было атрымана 1506 фрагментаў метаданых. Яны былі захаваны ў базе даных GeoNetwork у выглядзе падшаблонаў і звязаны з шаблонам метаданых для фарміравання 251 новага запісу метаданых.
