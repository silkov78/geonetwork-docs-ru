# Кіраванне стандартамі метаданых

Запісы метаданых у GeoNetwork апісваюцца схемай. 
Схема вызначае структуру запісу метаданых і прадастаўляе ўсе дапаможныя даныя і функцыі для выкарыстання схемы ў GeoNetwork.

Магчымасць падключэння схемы метаданых была ўведзена ў GeoNetwork 2.8.0. У версіі 3.0.0 магчымасці плагінаў былі пашыраны, 
каб палегчыць той факт, што плагіны могуць утрымліваць java-код.

!!! Папярэджанне!

    Даданне ў GeoNetwork няправільнай або несапраўднай схемы метаданых можа прывесці да сур'ёзнай паломкі вашага экзэмпляра GeoNetwork. Гэты раздзел прызначаны для адміністратараў каталога, якія добра разбіраюцца ў схемах метаданых і разумеюць розныя тэхналогіі, звязаныя са схемай метаданых GeoNetwork.


Падрабязнае апісанне таго, што ўяўляе сабой схема метаданых для GeoNetwork, можна знайсці ў Кіраўніцтве для распрацоўшчыкаў GeoNetwork. 
У гэтым раздзеле апісваецца, як атрымаць доступ да функцый дадання, абнаўлення і выдалення схемы і як гэтыя функцыі варта выкарыстоўваць.

!!! Папярэджанне!

    Схемы метаданых павінны быць старанна пратэставаныя ў экзэмпляры распрацоўкі GeoNetwork **да** таго, 
    як яны будуць разгорнуты ў вытворчым экзэмпляры. Памылкі ў плагіне схемы (асабліва ў XSLT прагляду) 
    могуць зрабіць ваш экзэмпляр GeoNetwork непрыдатным для выкарыстання.


    ``` xml
    <module>{myschema}</module>
    ```

- Дадайце спасылкі на толькі што дададзеную схему ў /web/pom.xml

    ``` xml
    <dependency>
      <groupId>${project.groupId}</groupId>
      <artifactId>{myschema}</artifactId>
      <version>${project.version}</version>
    </dependency>
    ```

-   і

    ``` xml
    <resource>
      <directory>${project.basedir}/../schemas/{myschema}/src/main/plugin</directory>
      <targetPath>${basedir}/src/main/webapp/WEB-INF/data/config/schema_plugins</targetPath>
    </resource>
    ```

Затым пабудуйце і разгарніце свой экзэмпляр GeoNetwork.
