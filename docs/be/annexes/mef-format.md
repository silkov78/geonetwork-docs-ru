# Фармат абмену метададзенымі (MEF) {#mef_format}

## Уводзіны

Фармат абмену метададзенымі (скарочана MEF) — гэта спецыяльна распрацаваны файлавы фармат для абмену метададзенымі паміж рознымі платформамі. Метаданыя, экспартаваныя ў фармаце MEF, могуць быць імпартаваны любой платформай, здольнай разумець MEF. Гэты фармат быў распрацаваны з улікам GeoNetwork, таму інфармацыя, якую ён змяшчае, у асноўным звязана з GeoNetwork. Тым не менш, яго можна выкарыстоўваць як фармат для забеспячэння сумяшчальнасці паміж рознымі платформамі.

Гэты фармат быў распрацаваны з улікам наступных патрэб:

1.  Экспарт запісу метададзеных для мэт рэзервовага капіравання.
2.  Імпарт запісу метададзеных з папярэдняй рэзервовай копіі.
3.  Імпарт запісу метададзеных з іншай версіі GeoNetwork для забеспячэння плаўнага пераходу ад адной версіі да іншай.
4.  Збор метададзеных, а таксама эскізаў і любых дадзеных, загружаных разам з запісам метададзеных.

У наступных параграфах некаторыя тэрміны варта разумець наступным чынам:

1.  Тэрмін **актар** (actor) выкарыстоўваецца для абазначэння любой сістэмы (прыкладання, службы і г.д.), якая працуе з метададзенымі.
2.  Тэрмін **чытач** (reader) будзе выкарыстоўвацца для абазначэння любога актара, які можа імпартаваць метададзеныя з файла MEF.
3.  Тэрмін **пісьменнік** (writer) будзе выкарыстоўвацца для абазначэння любога актара, які можа генераваць файл MEF.

## Фармат файла MEF v1

Файл MEF — гэта проста ZIP-файл, які змяшчае наступныя файлы:

``` text
Корань
 |
 +--- metadata.xml
 +--- info.xml
 +--- public
 |        +---- усе публічныя дакументы і эскізы
 +--- private
           +---- усе прыватныя дакументы і эскізы
```

1.  *metadata.xml*: гэты файл змяшчае самі метададзеныя ў фармаце XML. Кадзіроўка тэксту метададзеных (напрыклад, UTF-8) указваецца ў XML-дэкларацыі.
2.  *info.xml*: гэта спецыяльны XML-файл, які змяшчае інфармацыю, што адносіцца да метададзеных (метаданыя пра метададзеныя). Прыклады інфармацыі ў файле info.xml: дата стварэння, дата змены, правы доступу. Гэтая інфармацыя неабходна для GeoNetwork.
3.  *public*: гэта каталог, які выкарыстоўваецца для захоўвання эскізаў метададзеных і іншых публічных файлаў. Абмежаванняў на фармат выяў няма, але настойліва рэкамендуецца выкарыстоўваць фарматы Portable Network Graphics (PNG), JPEG або GIF.
4.  *private*: гэта каталог, які выкарыстоўваецца для захоўвання ўсіх дадзеных(карт, шэйп-файлаў і г.д.), загружаных разам з метададзенымі ў рэдактары GeoNetwork. Файлы ў гэтым каталогу з'яўляюцца *прыватнымі* ў тым сэнсе, што для доступу да іх патрабуецца аўтарызацыя. Абмежаванняў на тыпы файлаў, якія могуць захоўвацца ў гэтым каталогу, няма.

Любыя іншыя файлы або каталогі, якія прысутнічаюць у файле MEF, павінны ігнаравацца чытачамі, якія іх не распазнаюць. Гэта дазваляе актарам дадаваць у файл MEF карыстальніцкія пашырэнні.

Файл MEF можа мець пустыя папкі `public` і `private` у залежнасці ад фармату экспарту, які можа быць:

-   *просты* (simple): і `public`, і `private` прапушчаны.
-   *частковы* (partial): прадастаўляюцца толькі публічныя файлы.
-   *поўны* (full): прадастаўляюцца як публічныя, так і прыватныя файлы.

Пры найменні файлаў MEF рэкамендуецца выкарыстоўваць пашырэнне `.mef`.

## Фармат файла MEF v2

MEF версіі 2 падтрымлівае наступнае:

-   падтрымка некалькіх метададзеных: у адным файле MEF можа захоўвацца больш за адзін запіс метададзеных і дадзеных.
-   падтрымка некалькіх схем: магчымасць захоўваць у адным MEF-файле `n` фарматаў (напрыклад, для профілю ISO таксама захоўваць версію гэтага запісу ў базавай схеме ISO19115/ISO19139).

Бягучыя службы экспарту, якія ствараюць файлы MEF з запісу метададзеных са звязанымі запісамі (напрыклад, бацькоўскім, каталогам аб'ектаў і г.д.), могуць уключаць гэтыя звязаныя запісы метададзеных у MEF.

Структура фармату MEF v2 наступная:

``` text
Корань
  |
 + 0..n metadata
     |
     +--- metadata
     |     +--- metadata.xml
     |     +--- (апцыянальна) metadata.iso19139.xml
     +--- info.xml
     +--- applschema
     |     +--- (апцыянальна) metadata.xml (Каталог аб'ектаў ISO19110)
     +--- public
     |     +---- усе публічныя дакументы і эскізы
     +--- private
           +---- усе прыватныя дакументы і эскізы
```

!!! Заўвага

    `metadata.iso19139.xml` генеруецца актарамі GeoNetwork пры экспарце, калі запіс метададзеных у `metadata.xml` з'яўляецца профілем ISO19115/19139. Пры імпарце гэты запіс можа быць выбраны для загрузкі, калі профіль ISO19115/19139 адсутнічае.


## Файл info.xml

Гэты файл змяшчае агульную інфармацыю пра метададзеныя. Ён павінен мець каранёвы элемент `info` з абавязковым атрыбутам `version`. Гэты атрыбут павінен быць у фармаце X.Y, дзе X уяўляе асноўную версію, а Y — мінорную. Мэта гэтага атрыбута — дазволіць у будучыні змяняць гэты фармат, захоўваючы сумяшчальнасць са старымі чытачамі. Палітыка ў дачыненні да версій наступная:

1.  Змена Y азначае нязначнае змяненне. Усе існуючыя элементы ў папярэдняй версіі павінны заставацца без змен: могуць быць дададзены толькі новыя элементы або атрыбуты. Чытач, здольны чытаць версію X.Y, таксама здольны чытаць версію X.Y' пры Y'>Y.
2.  Змена X азначае буйное змяненне. Звычайна чытач версіі X.Y не зможа прачытаць версію X'.Y пры X'>X.

Каранёвы элемент павінен мець наступныя даччыныя элементы:

1.  *general*: кантэйнер для агульнай інфармацыі. Ён павінен мець наступныя даччыныя элементы:
    -   *uuid*: гэта ўніверсальны ўнікальны ідэнтыфікатар, прысвоены метададзеным, і ён павінен быць сапраўдным UUID. Гэты элемент з'яўляецца неабавязковым, і, калі ён прапушчаны, чытач павінен яго згенераваць. Метаданыя без UUID могуць быць імпартаваны некалькі разоў у адну і тую ж сістэму без парушэння абмежаванняў унікальнасці. Пры адсутнасці `uuid` чытач таксама павінен згенераваць значэнне `siteId`.
    -   *createDate*: гэтая дата паказвае, калі былі створаны метададзеныя.
    -   *changeDate*: гэтая дата адсочвае апошнюю змену метададзеных.
    -   *siteId*: гэта UUID, які ідэнтыфікуе актара, які стварыў метададзеныя, і павінен быць сапраўдным UUID. Калі элемент `uuid` адсутнічае, гэты элемент таксама павінен адсутнічаць. Калі ён прысутнічае, ён будзе праігнараваны.
    -   *siteName*: гэта чытэльная для чалавека назва актара, які стварыў метададзеныя. Ён павінен прысутнічаць толькі ў тым выпадку, калі прысутнічае `siteId`.
    -   *schema*: назва схемы для запісу метададзеных у `metadata.xml`. Калі MEF імпартуецца актарам GeoNetwork, гэта назва павінна быць назвай схемы метададзеных, якая апрацоўваецца актарам (напрыклад, `iso19139`). Калі ў актара GeoNetwork няма такой схемы, ён можа паспрабаваць выбраць іншыя метададзеныя са схемай, якая прысутнічае (напрыклад, метададзеныя ў `metadata-iso19139.xml` могуць быць загружаны, таму што схема `iso19139` прысутнічае).
    -   *format*: указвае фармат экспарту MEF. Значэнне элемента павінна належаць наступнаму набору: { *simple*, *partial*, *full* }.
    -   *localId*: гэта неабавязковы элемент. Калі ён прысутнічае, ён указвае ідэнтыфікатар, які выкарыстоўваецца лакальна актарам `sourceId` для захоўвання метададзеных. Яго мэта — проста дазволіць паўторна выкарыстоўваць той жа лакальны ідэнтыфікатар пры паўторным імпарце метададзеных.
    -   *isTemplate*: лагічнае поле, якое ўказвае, ці з'яўляюцца гэтыя метададзеныя шаблонам для стварэння новых. Рэальнага адрознення паміж сапраўднымі метададзенымі і шаблонам няма, але некаторыя актары выкарыстоўваюць яго для хуткага стварэння метададзеных. Значэнне павінна быць: { *true*, *false* }.
    -   *rating*: гэта неабавязковы элемент. Калі ён прысутнічае, ён указвае карыстальніцкі рэйтынг метададзеных у дыяпазоне ад 1 (дрэнная ацэнка) да 5 (выдатная ацэнка). Спецыяльнае значэнне 0 азначае, што метададзеныя яшчэ не былі ацэнены. Можа выкарыстоўвацца для сартавання вынікаў пошуку.
    -   *popularity*: яшчэ адно неабавязковае значэнне. Калі яно прысутнічае, яно ўказвае на папулярнасць метададзеных. Значэнне павінна быць станоўчым, і высокія значэнні азначаюць высокую папулярнасць. Крытэрыі, якія выкарыстоўваюцца для вызначэння папулярнасці, застаюцца на меркаванне пісьменніка. Яго асноўная мэта — забяспечыць парадкаванне метададзеных пры пошуку.
2.  *categories*: кантэйнер для катэгорый, звязаных з гэтымі метададзенымі. Катэгорыя — гэта проста назва, напрыклад, 'audio-video', якая класіфікуе метададзеныя для палягчэння пошуку. Кожная катэгорыя задаецца элементам `category`, які павінен мець атрыбут `name`. Гэты атрыбут выкарыстоўваецца для захоўвання назвы катэгорыі. Калі катэгорый няма, элемент `categories` будзе пустым.
3.  *privileges*: кантэйнер для правоў доступу, звязаных з гэтымі метададзенымі. Правы доступу — гэта аперацыі, якія група (якая прадстаўляе набор карыстальнікаў) можа выконваць з метададзенымі, і яны задаюцца наборам элементаў `group`. Кожны з іх мае абавязковы атрыбут `name` для захоўвання назвы групы і набор элементаў `operation`, якія выкарыстоўваюцца для захоўвання дазволеных аперацый з метададзенымі. Кожны элемент `operation` павінен мець атрыбут `name`, значэнне якога павінна належаць наступнаму набору: { *view*, *download*, *notify*, *dynamic*, *featured* }. Калі груп няма або ў актара няма паняцця групы, элемент `privileges` будзе пустым. Элемент `group` без якіх-небудзь элементаў `operation` павінен ігнаравацца чытачамі.
4.  *public*: усе эскізы метададзеных (і любыя іншыя публічныя файлы) павінны быць пералічаны тут. Гэты кантэйнер змяшчае элемент `file` для кожнага файла. Абавязковымі атрыбутамі гэтага элемента з'яўляюцца `name`, які ўяўляе імя файла, і `changeDate`, які змяшчае дату апошняй змены файла. Элемент `public` з'яўляецца неабавязковым, але, калі ён прысутнічае, ён павінен утрымліваць усе файлы, якія прысутнічаюць у публічным каталогу метададзеных, і любы чытач, які імпартуе гэтыя файлы, павінен усталяваць для іх дату апошняй змены, выкарыстоўваючы прадастаўленыя значэнні. Мэта гэтага элемента — прадаставіць больш інфармацыі ў выпадку, калі фармат MEF выкарыстоўваецца для збору метададзеных.
5.  *private*: гэты элемент мае тую ж мэту і структуру, што і элемент `public`, але адносіцца да карт і ўсіх іншых прыватных файлаў.

Любы іншы элемент або атрыбут павінен ігнаравацца чытачамі, якія іх не разумеюць. Гэта дазваляе актарам дадаваць у XML карыстальніцкія атрыбуты або паддрэвы.

### Фармат даты {#info_xml}

Калі не пазначана іншае, усе даты ў гэтым файле павінны быць у фармаце ISO/8601. Шаблон павінен быць ``YYYY-MM-DDTHH:mm:SS``, а часавы пояс павінен быць лакальным.

Прыклад файла `info.xml`:

``` xml
<info version="1.0">
    <general>
        <uuid>0619abc0-708b-eeda-8202-000d98959033</uuid>
        <createDate>2006-12-11T10:33:21</createDate>
        <changeDate>2006-12-14T08:44:43</changeDate>
        <siteId>0619cc50-708b-11da-8202-000d9335906e</siteId>
        <siteName>FAO main site</siteName>
        <schema>iso19139</schema>
        <format>full</format>
        <localId>204</localId>
        <isTemplate>false</isTemplate>
    </general>
    <categories>
        <category name="maps"/>
        <category name="datasets"/>
    </categories>
    <privileges>
        <group name="editors">
            <operation name="view"/>
            <operation name="download"/>
        </group>
    </privileges>
    <public>
        <file name="small.png" changeDate="2006-10-07T13:44:32"/>
        <file name="large.png" changeDate="2006-11-11T09:33:21"/>
    </public>
    <private>
        <file name="map.zip" changeDate="2006-11-12T13:23:01"/>
    </private>
</info>
```
